## Design synthesis

The flagship workspace is map first, with a narrow navigation rail, a concise metric strip, a large geographic panel, a selectable fleet list, and a contextual telemetry panel. The typography separates human-readable aircraft names from tabular technical values. Amber indicates selection or simulated warning, teal indicates healthy connectivity, and red indicates an actionable failure. Dense information stays in panels with consistent headings and clear units. The mobile experience emphasizes fleet status and the selected aircraft while keeping map exploration available.

The design improves on the available references by keeping the observation-only boundary explicit, marking all demo values as simulated, showing stale-stream state, and linking aggregate readiness back to aircraft records. The requested production consoles were not accessible, so any comparison of their exact visual quality would be speculation.

## Source-data decision

Use fictional deterministic flights for the initial replay. PX4's [public log access policy](https://review.px4.io/) permits public browsing but warns that logs may include location data. A ULog import is a later, separately tested feature with source attribution and per-field validation.
